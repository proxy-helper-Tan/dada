1

Get your NVIDIA API key (2 minutes)

  1. Go to build.nvidia.com and sign up with your email (no credit card needed)
  2. Open any model page and click "Get API Key" → Generate Key
  3. Copy the key immediately — it starts with nvapi- and is shown only once
💡 Keep it safe Treat this key like a password. You will paste it into Render in Step 3 — never into JanitorAI, never into chat messages, never into GitHub.
2

Put the proxy code on GitHub (3 minutes)

  1. On GitHub: click + (top right) → New repository
  2. Name it my-proxy → set to Public → Create repository
  3. On the empty repo page, click "uploading an existing file"
  4. Copy each file below with its Copy button, save it on your PC with the exact same filename, then drag all of them into the GitHub upload area
  5. Click Commit changes
⚠️ Filenames matter The files must be named exactly server.js, package.json, render.yaml and prompt.txt, sitting at the top level of the repo — not inside a subfolder, or Render will not find them.
server.jsthe proxy itself (v3.3, password-protected)
package.jsontells Render how to run the proxy
render.yamldefault settings for Render
prompt.txtthe narrator rulebook — full version included below
💡 How prompt.txt works The proxy injects these narrator rules into every request server-side, so every bot you chat with follows them automatically — no need to paste rules into each character's Custom Prompt field in JanitorAI. If rules are already written inside a character's Custom Prompt, remove them there so they are not sent twice. The rulebook above is complete and battle-tested; you can replace its contents with your own rules anytime (then redeploy on Render).
3

Turn it into a live website on Render (3 minutes)

  1. Go to render.com → sign in with GitHub
  2. Top bar → + New → Web Service
  3. Connect GitHub (one time only): if the page says "No repositories found", click the GitHub button on it → authorize Render → choose All repositories (or select my-proxy) → Save. Your repos then appear in the list
  4. Click your my-proxy repo in the list
  5. On the config screen check: Language Node, Branch main. Build and Start commands autofill (e.g. yarn install / yarn start or npm install / npm start) — either is fine, no need to change
  6. Scroll down to Compute and click the Free plan ($0/month, 0.1 CPU, 512 MB) — see the warning below
  7. Scroll to Environment Variables: delete the NAME_OF_VARIABLE placeholder row if present, then add the variables from the table below
  8. Click Deploy Web Service and watch the build log for 2–3 minutes
  9. Copy your new URL at the top of the page (looks like https://my-proxy-abc123.onrender.com)
⚠️ The $7/month trap — do not skip The Deploy button shows the price of the currently selected plan. Render defaults new services to a PAID plan, so the button may say "$7 / month". Scroll up to the Compute section and click the Free $0/month option BEFORE deploying. If you ever deploy a paid service by accident: open the service → Settings → Delete Service immediately.
💡 About Projects Render organizes services into projects — think folders. Render creates a default project for you, and you can make more anytime with "+ Create new project". It does not matter which folder your proxy lives in — the service works identically. To choose a folder at creation time, use the "Project (Optional)" dropdown on the config screen. To rename or manage a folder later: Projects → open it → Settings.

Newer JanitorAI update? Proxy presets and thinking levels

If your account has the newer proxy settings screen (a saved list of proxies, each with its own name, Proxy URL, API key and Model), everything above still applies — just in nicer packaging. Three things to know:

  • Request format → choose "OpenAI-compatible". It means "this API speaks OpenAI's request/response format" — which is exactly what this proxy does. Pick OpenRouter only if your URL points at openrouter.ai, and Custom/third-party for anything else.
  • Supported thinking levels: tick the levels you want JanitorAI to use (Low / Medium / High / Max...). With OpenAI-compatible selected, JanitorAI sends your choice as reasoning_effort, and the proxy passes it straight to NVIDIA. The REASONING_EFFORT env var in Render becomes just the fallback for when JanitorAI sends nothing.
  • Custom prompt → leave "None". Your narrator rules already live in prompt.txt inside the proxy — adding them here too would send them twice.

🔒 Security — read this before sharing anything

  • Your NVIDIA key never touches GitHub or JanitorAI. It only lives in Render's environment variables. Sharing the code files is completely safe.
  • Never post your proxy URL publicly. Even with a password, the URL plus a leaked or guessed password means strangers can burn your free ~40 requests/minute quota. Everyone should deploy their own copy — this guide makes that a 10-minute job.
  • Set CLIENT_AUTH_KEY. Requests without the correct password get a 401 error and never reach NVIDIA.
  • Think your key leaked? Go to build.nvidia.com → generate a new key → update NIM_API_KEY in Render → Manual Deploy → Deploy latest commit. The old key dies instantly.
  • Check your proxy's status anytime: open https://your-url.onrender.com/health — it shows whether the key, password, and thinking settings are active. This page is safe to share: it reveals no secrets.
